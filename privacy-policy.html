SAFE IMAGE SAVE

Privacy policy

Last updated: 2026-10-23

What the extension handles

When you explicitly choose an image action from the right-click menu, Safe Image Save converts that selected image locally in your browser. Your browser requests the selected image from its existing source, which receives the normal network request and connection details. Safe Image Save does not upload converted image pixels to the developer, an analytics provider, or a remote conversion service.

Optional access for X images

For images hosted on X's pbs.twimg.com CDN, Chrome asks for optional access after you select the image. If you allow it, the extension requests only the selected image with cookies omitted and no page referrer, then converts it locally. X's image CDN receives that request, but the converted pixels and local settings are not sent to X, the developer, or a converter service. The permission is not requested during installation and can be revoked in Chrome's extension settings. If you deny it, no image is downloaded.

What is stored locally

The extension stores your format, quality, filename, and history preferences in local extension storage. When local history is enabled, it stores filenames, output formats, site names, dates, file sizes, and the browser download identifier. It does not store image pixels or full browsing history.

What the extension does not do

Safe Image Save does not use accounts, analytics, affiliate links, ads, remote conversion services, background page scanning, or remote code. It does not sell local data or use it for purposes unrelated to image conversion.

Your controls

You can turn local history off or clear it at any time from the extension popup. Removing the extension removes its local storage according to the browser's extension-data behavior.

Browser limits

Some sites other than X prevent local pixel access to their images. In that case the extension refuses the conversion rather than uploading the image or saving a mislabeled file. Animated GIFs exported to another format use the first frame. Very large images are refused to limit memory use, and AVIF depends on browser support.
